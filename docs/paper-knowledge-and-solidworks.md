# Article knowledge and native SolidWorks geometry

The knowledge pack preserves reusable evidence. The Paper2Simu input ledger records what the current case adopts and why. CAD_BRIEF.md records how the adopted dimensions drive a particular native model and configuration. Link records by reference so later revisions can be traced without copying approvals into another store.

## Article knowledge packs

1. Use locally available textbook-to-skill in knowledge-pack mode. Reviewed revision: https://github.com/tsuntungngaing-jtn/textbook2skill/tree/1af584c24d6639af65f8eab0b7c0236286507779 (v0.3.0). Read source-ingestion, PDF pipeline, extraction, output-contract and, where useful, knowledge-system references. Check actual version/script help if local revision differs. Inventory article, edition, supplements, DOI/document identity, source ID, hash where bytes available, access and redistribution rights. Include printed page and 1-based PDF page, section anchor, table/equation/figure panel.
2. In the authorized task directory, create a new pack using upstream scripts/init_pack.py <pack-dir>. Maintain coverage.json. Run upstream scripts/pdf_pipeline.py native <source.pdf> <private-sidecar-dir> --start <first-page> --end <last-page> in companion environment where available. Use optional semantic tooling for difficult layouts. Verify dimensions, table headings/units, notation and figure labels against original pages. If companion is unavailable, use an available local reader and the existing [paper input workflow](../prompts/paper-input-reconstruction.md); report unavailable tools and unread sources.
3. Fill source-index.json, coverage.json, concept/rule/formula JSONL and workflow/validation notes as applicable. Prioritize geometry definitions, equations and validity ranges, material/BC definitions, methods and QoI/benchmark definitions. Distinguish direct evidence, derivation, inference and external supplementation. Keep conflicts, missing conditions, estimates and inaccessible evidence visible. Use stable IDs across papers; keep regimes and definitions distinct. Use the optional companion graph only when useful for linking a larger corpus; its structural checks and multi-hop retrieval do not certify evidence. Keep PDFs, page renders, OCR and protected material private.
4. Run upstream scripts/validate_pack.py <pack-dir> when available; separate structural status from source review. Before applying a card, retrieve relevant material and check original evidence, units and applicability. Record card ID, pack revision or manifest hash, source ID/locator, quantity/unit, conversion or derivation in the existing input ledger. Follow [source precedence](authoritative-source-precedence.md) and active reproduction ledger rules. A reviewed reusable card is contextual evidence; it cannot lock an input, clear a veto, authorize a solve or promote an RSI rule. Keep held-out papers out of retrieval and learning for reserved evaluations. When two sources disagree, retain both, compare definitions/regimes and obtain independent review rather than treating a graph edge or majority as truth.

## Native SolidWorks modeling

Use native references from locally installed solidworks-cad-modeling or reviewed upstream revision https://github.com/tsuntungngaing-jtn/solidworks-cad-modeling/tree/45e3e2a7d90c8e7f94659411ffab4c8b9bbda5a6. Read references/workflow.md, local-environment.md, native-com.md, modeling-patterns.md and validation-handoff.md as applicable. Skip DFM/DFA, manufacturing optimization and fabrication review. Fit, contact, connectivity and overlap checks remain relevant when needed for geometry and simulation.

1. **Environment and source:** verify actual Windows SolidWorks COM session/build, templates, supported APIs and export on this host. Upstream paths are examples, not local evidence. Inspect features, bodies, configurations, units and external references before editing task-owned copies. Without native access, prepare brief and authorized independent checks; report native modeling BLOCKED. One writer per native document; for mixed tasks preserve v0.5.1 Executor/admission rules and verify tool isolation for CAD writes. CFD access does not imply SolidWorks access.
2. **CAD_BRIEF.md:** record origin, axes, units, physical domains, interfaces, case/configuration, dimensions, feature sequence and expected measurements. For every driving parameter, record stable name, value/unit, exact source locator or user requirement, evidence status and affected features; link ledger/card when available. Missing dimensions stay assumptions or unresolved, bounded variants only if useful to task. Schematic establishes dimension endpoints but not exact length. Pixel estimates require justified scale and uncertainty; verify units at native API boundary (e.g. mm to m for SolidWorks COM length inputs).
3. **Editable source:** datum geometry, constrained sketches, named dimensions/equations, stable features/configurations; simplest sequence preserving physical domains. Separate bodies/components if required for materials or simulation regions. Use native mates where appropriate. Deliver SLDPRT or SLDASM with part dependencies and authoritative configuration; report reference/imported bodies and actual editability.
4. **Editability evidence:** rebuild each delivered configuration, read active configuration, feature errors/warnings, dimensions and geometry. On task-owned copy change a driving dimension, rebuild, measure predicted geometric response, restore baseline, verify again. Save and reopen finalized disk files and recheck dimensions, references and geometry. Record measured values, units, tolerances, status; unperformed checks NOT_RUN. Provide actual model views when useful.

## Handoff to COMSOL or Fluent

1. Export STEP from verified native configuration when requested. Record native files, SolidWorks build/configuration, STEP hash, format/unit, axes/transform, envelope and key body measurements. Independently reopen STEP; compare solid count, validity, bounds, critical dimensions/volumes, intended contacts/gaps/overlaps. Record solver roles (fluid, solids, inlet, outlet, interface) using semantic names and identifying geometric conditions. Names and face numbers may change.
2. In COMSOL use configured MCP and [geometry import workflow](geometry-workflow.md#cad-workflow) for actual build and CAD Import entitlement. Specify source units, transforms, repair tolerances and union/assembly/interface policy. In Fluent verify actual geometry/meshing provider and import route separately from solver connection. If unavailable, retain verified CAD deliverables and mark dependent work blocked.
3. Read back imported geometry and map semantic roles using position, area, normal, adjacency, connectivity and expected counts. Verify fluid/solid distinctions and boundaries/interfaces before binding materials, mesh or physics. STEP export, native import, selection binding and scientific acceptance are separate results. Retain native feature tree in original CAD. On dimension change record new input revision, rebuild and re-export, verify new hash, reimport and rebind. Dependent mesh, physics bindings and solution evidence are stale until checked against new geometry.

Illustrative example: a paper table states channel width 1.20 mm; cite the table in pack and ledger, map to ChannelWidth in CAD_BRIEF, read back chosen SolidWorks configuration, temporarily edit and restore, verify exported STEP width. On solver import verify actual fluid channel and inlet/outlet faces. A schematic-derived width stays an inference throughout. No model is created or solver connected by loading this document.

## Verification status

The workflow is an integration contract and not a new installed CAD/CFD driver. The companion packages are versioned separately, and no external package installation, solver license, live native edit, import or scientific reproduction is implied by this release. Do not transfer original papers, credentials or private model artifacts to the public repository.
