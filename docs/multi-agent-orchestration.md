# Paper2Simu 0.5.0 — evidence-gated multi-agent orchestration

## Scope
0.5.0 extends 0.4.5 without changing numerical criteria, native providers or solver budgets. This is a host-executed orchestration skill, not a new agent service. Native and actual subagent execution NOT_RUN. Parent = orchestrator + sole Executor. Specialists read snapshots only. Deterministic code checks handoffs, budgets and artifacts; no extra LLM recorder. Do not start a persistent supervisor subagent, spawn recursively, or use agents merely to count them.

## Deployment
Codex custom TOML roles in .codex/agents/ are supported at project root or user-level ~/.codex/agents/ (see [official Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)). When installing the skill into a skills directory, its nested .codex directory is not automatically a workspace agent directory. Review and explicitly copy just the five prefixed TOML files into the trusted simulation workspace's .codex/agents/ or personal agent directory; do not overwrite existing files or change existing connector configuration. Verify registered role names and spawn/wait capability in a new session. Optional project setting agents.max_concurrent_threads_per_session=3 (older max_threads alias); do not change host global settings silently. Role files use read-only sandbox; this does not prove MCP isolation because workers can inherit MCP tools. Before delegation confirm effective worker tool restrictions or use a verified isolated document-only worker environment with no solver mutation tools or solver credentials; if unavailable, do not delegate. No token or endpoint secrets are shared. Prompt restrictions are not a security boundary. Keep a single writer via existing provider ownership; this release does not implement a distributed lease or MCP ACL. If unavailable record SINGLE_AGENT_FALLBACK with reason, not a multi-agent result.

## Trigger and routing
For a multi-stage reproduction at intake, dispatch paper_reader and documentation_expert in parallel once inputs/version available; parent validates sources and freezes task ledger. For existing model edits skip irrelevant paper_reader. At reverse precheck dispatch physics_reviewer with readbacks and frozen criteria, without executor verdict. Parent resolves blocking findings or leaves dependent stage HOLD. Only parent executes MCP operations. At terminal solve or suspicious monitor event, dispatch supervisor with native evidence; for anomaly dispatch recovery_agent and documentation_expert if needed, using prior attempts and failure history. Independent hypotheses can run concurrently; dependent decisions wait. Do not delegate repetitive polling; host checks job metadata and budgets under native workflow. At delivery supervisor reviews fresh run/solution/dataset and evidence. Close completed worker threads; cap concurrent specialists at min(host limit, 3, task budget); count token/time separately. No nested delegation. If any role is unavailable, record missing/fallback and do not pretend independence. No extra commercial solver calls unless covered by same task budget.

## Handoff
Create one immutable assignment per role using schemas/agent-task.schema.json. Include assignment_id, task_id, case_id, role, stage, spec_hash, revision, snapshot_hash, permitted evidence_refs, question, deadline_utc. Parent stores assignments/results as new task journal artifacts (not repository). No worker writes canonical ledger. A result must echo assignment identity and evidence scope; only bounded findings and source refs. Check with python scripts/check_agent_handoff.py task.json result.json . Schema/identity pass is not evidence truth or permission. Parent cross-checks cited evidence and actual readbacks, resolves contradictory findings explicitly (source precedence), verifies current revision and deadline at use time. Old results after mutation are stale; redispatch with new snapshot or rerun affected checks. Do not aggregate by majority vote or treat agreements as proof. Late, missing or incompatible results block dependent checks only. Parent records dispatch IDs, role/version, start/end, token counts if available, fallback and reasons; resume reconciles actual outstanding worker and solver IDs. Do not recreate unresolved solver submissions. If subagents disappear, recover immutable snapshots and rerun only evidence tasks where useful. Do not reset time budget.

## Recovery integration
Supervisor signals anomaly; recovery_agent proposes options, documentation_expert validates supported properties, physics_reviewer checks target invariants as needed. Parent evaluates via shared supervision_decision.py and task's scope, checks live idle/identity/capability and checkpoint. Parent applies one mechanism, reads back and retests original criteria; independent reviewer inspects new result. KEEP/REVERT/HOLD use unchanged 0.4.5 rules. No agent may authorize own proposal. Do not lower thresholds, alter frozen physical assumptions or bypass MCP. Hard deadlines remain unsupported on shared JVM per deadline contract. Continue independent work when dependent stage blocked.

## Evaluation
Matched baseline release/paper2simu-0.4.5 versus 0.5.0 with same solver build, host, paper set, QoI definitions, per-case time/solve/retry budgets, and comparable model/token budgets. Record actual role invocation, fallback, wall time, tokens, solver calls, invalid API proposals, evidence extraction accuracy, false acceptance, recovery success, human interventions, scientific/reproduction outcome. Keep paired cases and held-out papers; no retrospective threshold tuning. Report intention-to-treat including fallback, and actual delegated runs separately. No claim of improved outcomes until measured.

Design references: [Towards a Science of Scaling Agent Systems](https://arxiv.org/abs/2512.08296), [Why Do Multi-Agent LLM Systems Fail?](https://arxiv.org/abs/2503.13657), [Foam-Agent](https://arxiv.org/abs/2509.18178), [Agentless](https://arxiv.org/abs/2407.01489). These motivate partitioning, bounded repair and validation; they do not validate Paper2Simu.
