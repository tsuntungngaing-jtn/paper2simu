# Paper2Simu v0.5.1 — knowledge-guided, fault-tolerant orchestration

Read [integrated system requirements](multi-agent-system-v0.5.1.md), [role registry](../agent-knowledge/registry.json), [native workflow](native-supervised-workflow.md) and existing task prompts. These supersede the 0.5.0 parent-as-writer rule for multi-agent mode. Baselines remain separate. Parent = Orchestrator only; nine specialists including sole Executor. Maximum three concurrent specialist threads by default, no nested delegation. Accuracy and independent evidence take priority over token savings; no redundant calls. This is a host-driven skill with offline guards, not a deployed daemon or enforced MCP ACL.

## Deployment and actual authority
Register nine reviewed prefixed TOML files from .codex/agents in the trusted workspace or user agent directory explicitly; do not overwrite local files. Orchestrator is the host, not a tenth spawned worker. Discover real spawn/wait/close and tool restrictions. Configure exactly one actual writer identity for the native session, separate read-only document workers from solver mutation tools and credentials. Executor may need host-specific MCP permissions; do not grant arbitrary shell or admin. Sandbox and TOML instructions do not enforce MCP rights. Verify actual isolation and supported operation identities before use; otherwise BLOCKED or explicitly authorized SINGLE_AGENT_FALLBACK under 0.4.5-like rules (not counted as multi-agent). No fallback may bypass a veto, time limit or unresolved job. No automatic connector installation, permission changes or scheduler setup.

## Dispatch protocol
Each assignment pins task/case/stage/revision/spec/snapshot hashes, deadline, allowed evidence, role profile and core knowledge manifest. Parent reads role registry, dispatches only required roles, stores immutable assignment/result plus actual worker IDs and receipt. Run scripts/check_agent_handoff.py and scripts/check_multi_agent_v051.py for declared handoff/knowledge/decision admission. The guard is offline: enforce in host/provider wrapper and recheck current native state; it cannot authenticate caller identity or grant authority. All critical reviews need distinct actual worker IDs from proposer/executor; preserve veto until fresh evidence and independent clearance. Readbacks and changed input/model/mesh revisions invalidate affected receipts. Parent never overrides a veto by majority vote. If genuine independent review unavailable report BLOCKED. Recorder summarizes; one deterministic journal writer appends original events including submission_started BEFORE submit; no competing journals. Reconcile original operations on resume.

Dispatch intake Paper Reader + Documentation Expert, Physics Reviewer and Supervisor at precheck, Executor for admitted native action; Supervisor reviews process event snapshots, Recovery Agent plus Documentation Expert when abnormal, Experiment Designer for authorized conditional trials, Acceptance Agent for independent final verification, Recorder at milestones and incident closure. Supervisory polling remains deterministic host work, requiring active host or configured scheduler. No implicit background promise. See [fault protocol](multi-agent-fault-recovery.md).
